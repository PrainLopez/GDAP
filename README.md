# A股总市值 vs GDP（巴菲特指标）

静态单页：三条线对比 —— 全部 A 股总市值（通达信 880001）、前四季度 GDP 之和、GDP × 70%；
另有一张巴菲特指标（总市值 ÷ 前四季度 GDP）图，带 70% 参考线。

## 数据（全部自动抓取）

```bash
node scripts/fetch.mjs         # 生成 data/data.js（GDP + 季度市值）
node scripts/fetch-weekly.mjs  # 生成 data/weekly.js（上季度初至今的周度市值）
open index.html                # 双击打开也行，无需起服务
```

- **总市值**：`scripts/tdx.mjs` 直连通达信标准行情服务器（TCP 7709），
  取 880001 的**季度 K 线**，每根 K 线的收盘即该季度最后一个交易日的收盘点位，
  点位 ×100 = 全部 A 股总市值（亿元）。内置多服务器故障切换。
- **GDP**：东方财富数据中心（转引国家统计局），由季度累计值差分得到单季值；
  每个位点的分母 = 该季度**之前四个季度**的单季 GDP 之和。

更新频率：GDP 公布日期不固定，由每周自动任务顺带刷新（见下文）。图表只显示 GDP 已正式公布的季度
（进行中的季度市值未收盘、与分母口径不齐，不展示）；当季 GDP 公布后该季度点自动出现。

## 自动更新（GitHub Actions）

单个 workflow 每周日自动运行（也可在 Actions 页面手动触发），同时刷新周度与季度数据：

- `.github/workflows/update-weekly.yml`：每周日运行 `scripts/fetch-weekly.mjs` 与 `scripts/fetch.mjs`，
  分别提交 `data/weekly.js` 与 `data/data.js`（数据无变化则不提交）。

配合 GitHub Pages（Settings → Pages → 选 main 分支根目录）即可完全无人值守。

## 运行机制与不稳定风险

**运行机制**：抓取脚本（Node，零依赖）→ 生成 `data/data.js` → 页面以 `<script>` 标签直接读取，
无构建、无后端、无数据库。GDP 走 HTTPS（东财数据中心），880001 走通达信行情协议（TCP 7709）。

可能失效的环节及应对：

- **通达信行情服务器**：公开免费节点，无 SLA。单台宕机已内置 5 台互备；若全部失效或所用网络
  拦截非 443 端口的 TCP 出向（部分公司网/代理会拦），在 `scripts/tdx.mjs` 的 `HOSTS` 换一批
  （搜索"通达信行情服务器 IP"）。协议若改版则需更新 `tdx.mjs` 的报文格式（参考 pytdx）。
- **东财 GDP 接口**：字段或接口地址可能调整，表现为脚本报错 `GDP 接口失败`，按报错改
  `fetch.mjs` 中的 URL/字段名即可。
- **GitHub Actions 定时任务**：仓库 60 天无提交，GitHub 会自动暂停 schedule。
  本项目有定时提交兜底，一般不会触发；真停了就在 Actions 页面手动跑一次。
- **数据起点 2011Q4**：880001 季度K线最早只到 2011Q4，因此全表统一从 2011Q4 起展示；
  更早的 GDP 数据仍会被脚本获取（一次接口调用），但仅用于计算 2011Q4 的分母
  （之前四个季度之和），不会出现在图表和输出数据中。
- **TanStack Charts CDN**：页面依赖 jsdelivr（react、react-dom、react-charts 三个 UMD 文件），
  访客首次打开需联网；jsdelivr 在个别网络下访问不佳时，可下载对应文件放入仓库并改为本地引用。
- **时间对齐**：横轴以已公布的 GDP 季度为准，市值点取该季度最后一个交易日的 880001 收盘
  （×100 = 总市值，亿元），分母为该季度之前四个季度的单季 GDP 之和，两边口径严格对齐。

## 手工覆盖

若某个季度想手工订正市值，在 `data/market_cap.manual.json` 添加（单位亿元）：

```json
[{ "quarter": "2025Q4", "value": 1050000 }]
```

## 缓存策略

`data/data.js` 会定期更新，缓存分两层：

- **浏览器缓存**：`index.html` 加载 `data.js` 时在 URL 后加时间戳 query
  （`data/data.js?t=...`），http(s) 访问下每次都拿最新文件；
  `file://` 双击打开时自动跳过 query（避免部分浏览器解析问题）。
- **托管方 CDN 缓存**：GitHub Pages 固定 `Cache-Control: max-age=600`（10 分钟），
  不可配置——数据更新后访客最多晚 10 分钟看到，对本项目（季度级数据）可接受。
  若改部署到 Netlify / Cloudflare Pages，可加 `_headers` 文件收紧：

  ```
  /data/*
    Cache-Control: no-cache
  ```

## 备注

- 页面通过 CDN 加载 TanStack Charts（react-charts），首次打开需联网。
- 通达信行情服务器为公开免费节点，若某天全部失效，在 `scripts/tdx.mjs` 的 `HOSTS` 里换一批即可
  （搜索引擎关键词：通达信行情服务器 IP）。

## Implementation Changes

## Calculation Rules
- 定投从开始日起按所选星期每七天生成计划，休市或净值缺失时顺延；超过结束日则取消，同一日多笔计划分别执行。
- 结束日为开始日加指定自然月，月末日期自动收敛；结束日非交易日时按此前最后一个行情日估值，不强制清仓。
- 股票和场内基金按计划日收盘价成交；场外基金按申请日净值成交。普通产品新份额 T+1 可卖，QDII T+2；可识别的债券、黄金、货币及跨境场内基金允许 T+0，无法识别时保守使用 T+1。
- 每个收盘日先执行此前生成的卖单，再执行当日定投，最后计算持有收益率并生成下一交易日卖单；不在期末之后成交。
- 持有收益率 = `当前市值 / 剩余持仓成本 - 1`，采用移动平均成本；卖出按比例结转成本，赎回款不再投入、不计利息。
- 向上触发为前一有效收益率 `< 阈值` 且当日 `>= 阈值`，向下反之；持续位于阈值另一侧不会重复触发，重新穿回后才可再次越过。
- 同日多条纪律先统一判定信号，下一有效交易日按用户排序依次卖出；每条按上一条成交后的剩余份额计算。受可卖份额限制时部分成交，未成交部分不补单。
- 允许全部卖出后继续定投；空仓期间持有收益率为空，不触发纪律。0% 规则保留但不产生交易。
- 开始或结束日期超出历史范围、没有可执行定投、金额/月数无效、阈值非有限数字或卖出比例不在 0–100% 时阻止计算并标明原因。
